Txt2Mesh is a pair of plugins, one for Cinema 4D and one for Unreal Engine, that let an artist type a plain-text description and get a finished 3D mesh back without ever leaving the software they already work in. No manual round-trip through a separate generation tool, no hunting through an output folder for the right file: type a subject, optionally attach a reference image, hit render, and the mesh shows up already imported into the scene.

Under the hood, each request is compiled into a ComfyUI workflow graph. A language model first expands the short prompt into a fuller, more descriptive one, which drives a text-to-image diffusion pass; that image is then handed to Hunyuan3D, which reconstructs it into a mesh. Three modes trade speed for fidelity: Geometry returns a fast, cleaned-up shape for blocking things out; Textured adds a full UV-unwrapped PBR paint pass; Textured HQ adds a further upscaling pass for hero assets. Geometry-mode meshes run through automatic post-processing, stray floating geometry removed, holes closed, normals smoothed, before reaching the artist; textured meshes skip that pass so the UV unwrap survives intact.

The plugin can drive either a small local ComfyUI instance it starts and manages itself, or a shared always-on render server with real GPU headroom, so the same interface scales from a quick idea on a laptop to a production asset on demand (a render-farm submission path exists too, kept in reserve for heavier batch loads). Everything generated, on any of these paths, is archived automatically to a shared library alongside its prompt and generation metadata, turning one-off experiments into a searchable, shared resource instead of loose files on someone's desktop.

The Unreal build is a second, independent implementation of the same idea rather than a shared codebase, deliberately built with zero cross-dependency on the Cinema 4D plugin so each stays self-contained. It reuses the identical backend contract, submit a prompt, poll a job, pull back a textured GLB, but had to solve a completely different UI problem. The original plan was to build the interface visually with Unreal's own editor-widget tools; a spike proved that widget layout can't be authored headlessly from Python, so rather than force a fragile workaround, the interface was rebuilt from scratch as a native compiled C++ panel wired to the same Python backend through a small string-passing bridge. It ships as a precompiled drop-in plugin, menu entry and all.

Two front ends, one backend contract: the same generative pipeline proven portable across engines, toolchains, and rendering topologies, from a laptop's spare GPU cycles up to a shared studio render server.
